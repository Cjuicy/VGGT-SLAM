# code-review-graph 中文使用说明

code-review-graph 把仓库源码解析为可搜索的节点与依赖边，并生成本地交互图和
主题说明。它适合在人工审查前回答“入口在哪里、谁调用它、哪些测试覆盖它”，
但不能替代阅读真实代码和运行测试。

## 生成文件

| 路径 | 用途 | 是否提交 |
| --- | --- | --- |
| `.code-review-graph/graph.db` | 本地结构化图数据库，供查询和增量更新使用 | 否 |
| `.code-review-graph/graph.html` | 可在浏览器中交互查看的单文件图 | 否 |
| `.code-review-graph/wiki/` | 按主题生成的本地说明页 | 否 |
| `.code-review-graphignore` | 项目级索引排除规则 | 是 |

`graph.db`、`graph.html` 和 `wiki/` 都能从当前源码重新生成，而且可能随工具
版本、绝对路径和本地状态变化。提交它们会制造大体积、频繁且难以审核的
diff，因此整个 `.code-review-graph/` 保持本地忽略。

本次生成图的规模为 43 个文件、207 个节点、1764 条边。重新生成后数字变化
是正常的，应以当次工具状态为准。

## 打开图

优先使用 code-review-graph 工具提供的打开或预览命令。若只需要查看已有
HTML，也可从仓库根启动本地 HTTP 服务：

```bash
python -m http.server 8000 --directory .code-review-graph
```

然后在浏览器打开：

```text
http://localhost:8000/graph.html
```

查看结束后在启动服务的终端按 `Ctrl-C`。不建议直接提交或分享
`graph.html`；需要交流结论时，把入口、调用链和真实文件行号写入审核文档。

## 常用控件

- **Search**：按文件、类、函数或符号名定位目标节点。先搜索明确入口，避免
  一开始阅读完整全局图。
- **Flows**：只显示工具识别出的某条执行流，适合从 CLI 或适配器入口追到
  合约、IO 和评测。
- **Communities**：按依赖密度聚类，帮助识别模块边界。聚类是辅助视图，不是
  Python 包边界的权威定义。
- **Fit**：把当前可见节点缩放到视口。全局图初次打开很密时先筛选再 Fit。
- **Labels**：控制节点文字显示。节点较多时关闭部分标签，选中局部后再打开。
- **Node filters**：按节点类型、目录或社区隐藏无关节点，例如只看函数和测试。
- **Edge filters**：按调用、导入、定义、`tests_for` 等关系筛选边，减少交叉线。

压缩后的全局图看起来很密是正常现象，不代表生成失败。不要试图同时读懂全部
节点；先缩小到一个入口、一条执行流或一个社区。

## 推荐审查流程

```text
Search target
-> select execution flow
-> inspect callers/callees
-> inspect tests_for
-> inspect impact radius
-> edit
-> detect changes
-> run real tests
```

具体做法：

1. 用 Search 找到要修改的 CLI、函数或数据合约。
2. 选择最相关的 Flow，检查上游调用者和下游被调用者。
3. 查看 `tests_for` 关系，定位现有单元测试和集成测试。
4. 扩大一层影响半径，检查共享 IO、配置和序列化契约。
5. 回到源码逐行确认，不依据图中的摘要直接修改。
6. 修改后运行工具的变更检测或增量更新，确认影响节点符合预期。
7. 最后运行仓库真实测试；图分析不能作为测试通过的替代证据。

## 能力边界

静态图可能无法完整识别运行时动态导入、反射、猴子补丁、字符串构造的模块名、
CUDA/设备分支以及由输入数据触发的控制流。VGGT-SLAM 中的回环数量、关键帧
选择、模型输出形状和显存行为都依赖实际数据与运行环境，必须在 AutoDL 真实
执行后审核。

图中的“没有调用边”也不等于代码不可达；先检查 CLI 模块入口、插件加载和
动态导入，再作删除判断。

## 本地配置边界

`.mcp.json`、`.claude/` 和 `CLAUDE.md` 是当前机器上由客户端或技能生成的
本地状态，可能包含绝对路径、钩子命令和个人工作流。它们不属于项目复现契约，
已在根 `.gitignore` 和 `.code-review-graphignore` 中排除，不应提交。

项目中需要共享的是本说明、`.code-review-graphignore`、代码审查结论和测试
证据，而不是某个客户端的本地数据库或配置。
